# 子任务继承父任务执行上下文设计

## 状态

已获用户确认，采用“继承父任务执行上下文”开关方案。

## 背景

任务可以通过父子关系拆分功能，例如：

```text
登录模块
├── 登录
├── 注册
└── 协议
```

同时，项目也会创建独立的探索类任务，例如研究 WebAuthn 或评估第三方认证服务。两类任务不能使用相同的上下文继承规则：功能拆分需要共享执行背景，独立探索应保持自主性。

当前任务模型已有：

- `Task.developmentContext`
- `Task.relations.parent`
- 创建任务时的 `parentId`
- 每个任务独立的 `threadBinding`

当前没有持久化的上下文继承开关。

## 目标

为子任务增加一个明确的“继承父任务执行上下文”开关，使功能拆分任务可以复用父任务的开发环境和只读背景，同时保证独立探索任务和 Codex 会话不被父任务污染。

## 非目标

本次不实现：

- 复制父任务描述到子任务；
- 复制父任务评论或附件；
- 继承负责人、状态、优先级、截止日期或标签；
- 共享父任务的 Codex `threadBinding`；
- 父任务状态自动驱动子任务状态；
- 多个父任务上下文合并。

## 开关定义

持久化字段建议为：

```text
inheritParentContext: boolean
```

字段归属子任务本身，不放在关系记录中。当前任务最多只有一个父任务，放在任务上可以避免为父子关系增加额外配置结构，也便于任务更换父任务后继续保持明确的独立/继承选择。

## 默认规则

### 从父任务创建子任务

如果用户在父任务范围内创建子任务，并在创建数据中明确设置了 `parentId`，默认：

```text
inheritParentContext = true
```

创建界面允许用户关闭这个默认值。

### 独立创建后再关联父任务

如果任务先以独立任务创建，之后才设置父任务，默认：

```text
inheritParentContext = false
```

后补父子关系不能悄悄改变原独立任务的执行方式；用户可以在任务详情中主动打开开关。

### 关系选择器关联已有任务

从任务详情的“添加子任务”关系选择器关联已有任务时，不自动覆盖该已有任务的继承开关。它保留已有任务当前设置，用户需要在子任务详情中主动调整。

## 继承内容

当 `inheritParentContext` 为 `true` 时，运行时解析以下内容。

### 开发上下文

使用优先级：

```text
子任务自己的 developmentContext
> 最近一级父任务的 developmentContext
> 更上层父任务的 developmentContext
> 项目默认 workspace
```

“继承”不复制父任务字段。父任务开发上下文发生变化时，未设置自身上下文且仍开启继承的子任务会在下一次运行时读取最新值。

### 父任务只读背景

启动子任务 Agent 时，附带：

- 当前任务编号和标题；
- 直接父任务编号和标题；
- 父任务目标/描述摘要；
- 父任务明确提供的技术约束或验收背景。

这些内容只进入执行指令，不写入子任务描述，不复制父任务评论或附件。

### 会话隔离

每个任务继续使用自己的 Codex `threadBinding`。子任务不得复用、覆盖或发送到父任务会话。

## UI 设计

### 创建任务

当创建表单选择父任务时，在父任务选择项附近显示：

```text
父任务：登录模块

☑ 继承父任务执行上下文
```

由父任务创建的子任务默认勾选；独立创建任务时不勾选。

### 任务详情

在“开发上下文”属性中显示来源：

```text
开发上下文
继承自：登录模块
```

提供开关：

```text
继承父任务执行上下文
```

关闭后显示当前任务独立执行。子任务自身配置了 `developmentContext` 时，仍可显示“当前任务配置”，并明确说明继承开关不会覆盖子任务自己的显式配置。

## 数据流

### 创建

1. `TaskEditor` 收集 `parentId` 和 `inheritParentContext`。
2. `App.saveEditor` 创建任务时写入字段。
3. 创建完成后继续使用现有父子关系写入流程。
4. 如果是独立创建后再关联父任务，不修改现有继承开关。

### 读取

1. API 返回任务时包含 `inheritParentContext`。
2. 前端任务类型和详情属性读取该字段。
3. 启动 Agent 前解析有效开发上下文和父任务摘要。

### 更新

1. 任务详情切换开关时更新当前任务版本。
2. 开关更新不改变父子关系。
3. 更新父任务开发上下文不需要批量写入子任务；运行时继承会读取最新值。

## 风险与边界

- 父链出现循环时，解析必须停止，不能无限遍历；沿用现有父子关系循环约束，并在运行时使用已访问集合。
- 子任务显式设置自己的 worktree 时，不能被父任务上下文覆盖。
- 父任务没有开发上下文时，继续回退到更上层父任务或项目默认 workspace。
- 父任务摘要应限制长度，避免把完整历史内容注入 Agent 指令。
- 不把父任务会话作为子任务会话目标。

## 验收标准

1. 从父任务创建子任务时，继承开关默认开启。
2. 独立创建任务后再关联父任务时，继承开关默认保持关闭。
3. 用户可以在任务详情中切换继承开关。
4. 开启继承且子任务无自身开发上下文时，子任务运行时使用父任务有效开发上下文。
5. 子任务有自身开发上下文时，父任务上下文不覆盖它。
6. 父任务上下文变化后，开启继承的子任务下一次运行读取最新上下文。
7. Agent 能获得父任务摘要，但使用子任务自己的 Codex 会话。
8. 独立探索任务不会因为后来建立父子关系而自动继承上下文。
9. 父任务、子任务的负责人、状态、优先级、评论、附件和会话仍彼此独立。

## 直接验证路径

实现后优先验证：

1. 在“登录模块”下创建“注册”，确认开关默认开启，并确认能看到父任务开发上下文来源。
2. 独立创建“探索 WebAuthn”，再关联到“登录模块”，确认开关默认关闭。
3. 为子任务设置自己的开发上下文，确认它优先于父任务。
4. 启动子任务 Agent，确认使用子任务会话并收到父任务摘要。
