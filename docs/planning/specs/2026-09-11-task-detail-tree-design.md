# 任务详情父子任务树设计

## 状态

已获用户批准，采用方案 A：前端递归树 + 详情导航历史。

## 背景与目标

当前任务详情中，父任务和子任务分别以两个平铺区域展示。目标是在任务详情中用一棵以当前任务为根的树展示全部后代任务，并让用户可以沿父子关系进入详情、返回上一层详情。

## 已确认范围

- 树替换当前详情中的父任务和子任务两个平铺区域。
- 当前任务是树根，只展示当前任务及其子任务、孙任务等后代。
- 父任务不作为树节点展示。
- 点击任意子任务节点进入该子任务详情。
- 从子任务详情返回，回到进入它的父任务详情。
- 从最初打开的任务详情返回，回到任务看板。
- 保留现有父子关系的添加、变更和移除能力。
- 从当前分支 `feat/multi-agent-auto-claim` 创建功能分支实现。
- 不新增后端树接口、不修改数据库结构、不使用 superpowers。

## 当前真实操作路径

1. 看板中的任务卡或列表项调用 `App.tsx` 的 `openTaskDetail()`。
2. `openTaskDetail()` 设置 `detailTaskIdentifier`，并通过 `buildIssueUrl()` 将任务详情写入浏览器历史。
3. `TaskDetail.tsx` 渲染任务详情，当前关系区域由 `IssueParentLink`、`IssueSubIssues` 和 `IssueRelationSidebar` 提供。
4. `IssueRelations.tsx` 从 `task.relations.parent` 和 `task.relations.subIssues` 渲染关系，并通过 `onOpenTask` 打开关联任务。
5. 顶部返回按钮调用 `closeTaskDetail()`，当前实现会直接关闭详情并回到看板；本设计将其调整为优先返回上一层任务详情。

## 方案

### 任务树数据

直接复用前端已有的 `tasks` 数组和任务关系字段：

- 根节点为当前 `task`。
- 子节点从当前任务的 `relations.subIssues` 获取。
- 通过 `tasks` 建立 `id -> Task` 索引，递归解析后代。
- 不新增 API、数据库字段或持久化结构。
- 关系变更成功后继续使用现有任务刷新/关系 mutation 流程，树从最新任务数据重新渲染。

### 任务树 UI

在 `web/src/components/IssueRelations.tsx` 中增加递归树节点组件，替换 `IssueParentLink` 和 `IssueSubIssues` 在 `TaskDetail.tsx` 中的使用。

每个树节点显示：

- 展开/收起控制（存在子任务时显示）。
- 任务状态图标。
- 任务编号。
- 任务标题。
- 子任务的负责人头像（沿用现有展示）。
- 当前已有的移除父子关系操作。

根节点额外提供：

- 添加子任务入口。
- 设置、变更或移除父任务的操作入口；父任务作为关系操作显示，不加入树节点。

默认状态：

- 根节点始终显示。
- 根节点的后代默认展开，确保用户进入详情即可查看完整结构。
- 用户可按节点收起或展开后代。

空状态：

- 没有子任务时仍显示当前任务根节点。
- 根节点提供添加子任务入口。

### 详情导航

沿用现有 URL 和 `popstate` 路由同步：

```text
看板 -> 父任务详情 -> 子任务详情 -> 孙任务详情
```

打开详情时：

- 如果当前已经在任务详情中，继续压入新的详情历史项。
- 如果从看板打开，保留现有看板返回入口。

返回时：

- 子任务详情返回到上一个任务详情 URL。
- 多级进入时按进入顺序逐级返回。
- 最外层任务详情返回看板。
- 浏览器后退与顶部返回按钮保持一致。

导航状态只服务于当前详情浏览，不新增任务数据字段。

## 交互与错误处理

- 点击树节点沿用现有 `onOpenTask` 回调。
- 关系保存和移除沿用现有 mutation、保存中状态和错误提示。
- 如果关联任务不在当前缓存中，不构造虚假的树节点；树只展示当前已加载且关系可解析的任务。
- 不增加与本次路径无关的防御性兼容层或全量关系重构。

## 验收标准

1. 打开有子任务的任务详情，看到当前任务为根的树。
2. 树能显示至少一层子任务，并能递归显示孙任务。
3. 子任务节点可点击进入子任务详情。
4. 在子任务详情点击返回，回到父任务详情而不是直接回到看板。
5. 多级进入时可以逐级返回。
6. 最外层详情返回看板。
7. 添加、移除或更换父子关系后，树结构正确更新。
8. 没有子任务时根节点和添加子任务入口仍可用。
9. 不影响阻塞、被阻塞和相关任务关系区域。

## 直接验证路径

实现完成后只验证用户报告的主路径和一个成功路径：

- 主路径：父任务详情 -> 子任务详情 -> 返回父任务详情。
- 成功路径：多级子任务树展示，并在关系变更后确认树更新。

不进行与本需求无关的全平台构建或全量回归扩展。
